# 0.1.1 verification report

Date: 2026-10-05. Project: `/storage/emulated/0/Ather-skill/code/mhy-scanner-android`.

## Fixed defect

Account enrollment reused the legacy **game** Panda QR login (`hk4e-sdk.mihoyo.com`, app_id=2), despite presenting the action as Miyoushe account login. The UI also depended on the game's `ticket` URL parameter, `stat` field, and `payload.raw` game-token response. Merely replacing the hostname would not fix that protocol mismatch.

Changed the full enrollment chain:

1. `POST https://passport-api.miyoushe.com/account/ma-cn-passport/app/createQRLogin` with an empty JSON body and BBS headers (`x-rpc-app_id=bll8iq97cem8`, device ID, client type 2, game_biz=bbs_cn).
2. Use **both** `data.url` and `data.ticket` returned by the server. The URL is a community `login-platform/mobile.html?...#/login/qr` link, not `qr_code_in_game.html`.
3. Poll `queryQRLoginStatus` using `{ticket}` and read `status=Created/Scanned/Confirmed`.
4. Require confirmed status, account `aid/mid`, and `tokens[token_type=1]` SToken. Do not treat LToken or the old game's `payload.raw` as a game token. Stop if official real-person verification is required.
5. Use the reference project's documented SToken → game_token exchange at the fixed official `api-takumi.mihoyo.com/auth/api/getGameToken` endpoint. Keep SToken only in memory; save the resulting game token in the existing encrypted vault.
6. Keep **game** `scan/confirm` endpoints unchanged for later authorized game-login sessions. These are deliberately separate from account enrollment.

UI labels now explicitly say Miyoushe. Failure messages distinguish QR creation, polling, and game-authorization exchange without printing credential-bearing URLs, token values, or response bodies.

After the fix, all **11 enrollment regression tests passed**. They also check BBS headers, empty create body, use of the server-returned ticket, community status parsing, selection/exchange of SToken instead of LToken, rejection of unconfirmed/verification-required sessions, and rejection of game/foreign QR URLs.

All fixture credentials are synthetic. Tests make no network requests and do not sign in real accounts.
