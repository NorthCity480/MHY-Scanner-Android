## Performance feedback loop

Red test: `LiveFramePumpTest` against a baseline model of 120 ms UI timer sampling. A decoded frame appearing 1 ms after a tick was not sampled immediately; 3 tests, 2 failures. Command: Gradle `:app:testDebugUnitTest --tests '*LiveFramePumpTest'`. Green: same three tests pass once new-rendered-frame callbacks directly reserve the single-flight decoder gate. The test verifies scheduling/queuing semantics using deterministic timestamps; **it is not an actual livestream end-to-end latency measurement**.

Ranked causes checked:

1. UI fixed timer waited up to the configured interval after the frame arrived. Eliminated by `TextureView.onSurfaceTextureUpdated()` and direct sampling of only newly rendered frames; optional zero-interval mode. Existing 60/120/250/500 ms settings remain available and saved preferences are preserved.
2. The old timer copied bitmaps before `FrameGate` could reject a busy decoder. New `ScanCoordinator.reserveLiveFrame()` claims the gate **before** `getBitmap()`; one frame in flight, no accumulating stale frames, rejected sessions recycle their bitmaps. Tests include busy/interval behavior; actual UI copy time is now observable in the status view. The app retains the last-rendered surface in the foreground; it does not scan in the background.
3. ZXing complexity on four upstream fixture screenshots plus a blank 960×540 bitmap was compared using a JVM-only 20–30 repetition warm benchmark. Median single QR vs current multi/TRY_HARDER was approximately 1–2 ms for both; no consistent improvement, so the more robust multiple-QR decoder was retained. These are **JVM measurements, not Android device decode timings**.
4. Player/network lag: progressive buffer bounds changed from 200–1500 ms to 150–650 ms and zero back-buffer; HLS `.m3u8` inputs request a 2000 ms live target with up to 1.08× catch-up. Unused audio selection is disabled (stream stays muted). These are tuning parameters, not measured guarantees; source/CDN segmentation can prevent the target or cause rebuffering. Android UI shows recent copy/decode durations and Media3's live offset when known. A real permitted live source is needed to determine and tune end-to-end latency and stability.

Safety unchanged: account consent remains per game-scan session; default manual confirmation; no real game-login confirm was submitted during this optimization; no bypass of official rate, verification or signatures.
